# AppLens v0.2.0: error collection, shared redaction, richer AI context, and a full docs rewrite

This upgrade adds end-to-end error collection (new `AppError` type, an observing `ErrorInterceptor`, synchronous storage methods, a 7th `Errors` tab, and Overview rows), extracts header redaction into a shared `redact` utility reused by the network interceptor, upgrades `JSONViewer` to colored syntax highlighting with horizontal scroll, enriches `ContextEngine` with error chunks and a context summary, and surfaces a context-used section plus a confidence badge and copy action in the AI tab. It also fixes the blocking `tsconfig` `moduleResolution` error that broke `tsc`, and rewrites README/DELIVERY/CHANGELOG to describe only what actually ships. Every change is additive at the export level, uses the existing dark theme, and introduces no new npm dependencies.

Watch for: the `ErrorInterceptor` preserves React Native's existing global handler by calling it after capture, so it observes rather than replaces (confirmed); error chunks are emitted into `ContextEngine` with `type: 'log'` rather than a dedicated error type because the `ContextChunk` union has no error member (confirmed, intentional); and `Clipboard` is imported from `react-native`'s deprecated API with a no-op fallback rather than a new dependency (confirmed).

**Verdict**: APPROVED

## High-level view

Error collection is wired the same way as the existing network/console interceptors: a boolean `config.errors` (default true) gates attach/detach, storage gains three synchronous methods (`addError`/`getErrors`/`clearErrors`) backed by a ring buffer, and the provider pushes errors into context so the Errors tab and Overview rows stay in sync. The interceptor is strictly observational — it saves and re-invokes the prior `ErrorUtils` handler and only enables the Hermes promise-rejection tracker when present, falling back to no-op.

Redaction logic that previously lived inline in `NetworkInterceptor` is now a shared `redact` utility. The default redaction set is all-lowercase, so the behavior is unchanged for shipped defaults; the extracted version additionally lowercases custom entries, which is a strict improvement for user-supplied keys.

The AI surface gained a `getContextSummary()` that mirrors what `getRelevantContext()` selects, rendered as a collapsible "Context used" section, plus a confidence badge parsed from the model reply and a copy button. The `OpenAIProvider` system prompt now asks the model to end with a `Confidence: High|Medium|Low` line; when absent, the badge simply doesn't render.

Config stays backward compatible — all prior fields remain, four new fields are added with defaults, and `index.ts` only adds exports. The `redaction` structured option and `persistLogs` are additive but not yet consumed by any interceptor; both are documented honestly as reserved/not-yet-wired, so there is no silent no-op surprise.

The docs rewrite removes previously fictional content (Zustand store, AsyncStorage-backed `persistLogs`, a `sensitiveHeaders` field) and aligns README/DELIVERY/CHANGELOG with the real API surface.

### ErrorInterceptor preserves the RN global handler

The behavioral property that matters: `attach()` saves `ErrorUtils.getGlobalHandler()` and, after storing the captured `AppError`, re-invokes the saved handler with the original `(error, isFatal)`, so React Native's red-box and the app's own error flow still run. It observes rather than replaces. `detach()` restores the saved handler. Promise-rejection capture is feature-detected on `global.HermesInternal.enablePromiseRejectionTracker` and stores rejections as non-fatal; when Hermes isn't present it's a no-op, and `detach()` disables the tracker by passing `null`. Ambient types for `ErrorUtils`/`HermesInternal` are declared locally, so no new dependency is pulled in.

### Shared redaction utility changes custom-key matching

The old inline `redactHeaders` lowercased only the incoming header key, while the extracted `../utils/redact` version lowercases both sides. The default `REDACTED_HEADERS` set is all-lowercase, so output is identical for shipped defaults; for user-supplied uppercase redaction keys the new version is strictly more correct. `redactFields` adds recursive, cycle-protected (WeakSet) field redaction without mutating input — but note it is not yet called by any interceptor (see Issues).

### ContextEngine emits error chunks as `type: 'log'`

`buildErrorChunks()` formats the top-5 recent errors as `[ERROR] ${message}\n${stack ?? ''}` with `relevanceScore 0.9`, emitted with `type: 'log'` because the `ContextChunk` union has no error member — a deliberate choice that keeps the type stable but means AI context does not distinguish errors from logs by type (they're distinguishable only by the `[ERROR]` prefix). Keyword matching now does bidirectional partial-substring matching.

### AI tab confidence badge and copy are fail-soft

Confidence is parsed with `/Confidence:\s*(High|Medium|Low)/i` and the badge is omitted when the model doesn't emit the line, so a non-compliant reply degrades gracefully. The copy button uses `Clipboard` from `react-native` wrapped in try/catch; this relies on the deprecated core `Clipboard` export, which still resolves and avoids adding `@react-native-clipboard/clipboard` as a dependency. If that export is removed in a future RN version the try/catch makes copy a silent no-op rather than a crash.

### JSONViewer preserves its prop API

The tokenizer re-scans `JSON.stringify(data, null, 2)` output, so the exact layout is kept and the `{ data, maxHeight? }` prop shape is unchanged — `ConsoleTab`/`EventsTab`/`NetworkDetailScreen` keep compiling. A guard falls back to `String(data)` when `JSON.stringify` returns `undefined`.

### Verification evidence

`npx tsc --noEmit` exits 0 on the branch (previously failed TS5095 until the `tsconfig` `moduleResolution` fix). `package.json` version is exactly `0.2.0` and the only changed line in that file is the version; no dependency entries were added. The modal renders 7 tabs with `Errors` between `Events` and `AI`, and tab/close/row touchables carry `accessibilityRole='button'`; the Errors FlatList `keyExtractor` returns `item.id`. README/DELIVERY/CHANGELOG match the shipped surface, with the fictional Zustand/AsyncStorage/`sensitiveHeaders` content removed and all 7 tabs plus the new APIs documented.
